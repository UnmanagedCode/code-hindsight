# Architecture

```
browser ── cc /plugins/code-hindsight/* ──► backend (node:http, 127.0.0.1:$PORT)
                                              ├─ /, /assets/*      shell UI (frontend/dist)
                                              ├─ /-/api/*          routes.js
                                              └─ everything else   cpProxy.js ──► <bind>:<cpPort>  CP container ─┐
                                                                                                                │ code-hindsight-net
                     supervisor.js ── docker.js ── docker | sudo -n docker ──► <bind>:<apiPort> API container ◄─┘
                                                                               └─ volume code-hindsight-data (.pg0)

Relay link (only while the LLM is linked to cc's Ollama backend or a loopback cc backend; one target at a time):
  API container ──http://<target alias>:<port> (relayKey)──► relay container  <prefix>-relay  (API-side port not published)
                                                                   ▲ pairs each API connection with one idle tunnel
  plugin: relayTunnel.js ──dials out──► <bind>:<relayPort> ─► relay :RELAY_TUNNEL_PORT
          └─ on pairing: relayProxy.js (key check, allowlist, credential injection) ──► the target: cc's Ollama daemon, or a loopback cc backend (both loopback in cc's container)
```

The Claude Code side is a plugin root, `claude/` (declared by `claudePlugin` in the manifest, so cc passes it to every session as `--plugin-dir`): `hooks/hooks.json`, `hooks/hook.mjs` (the one entry), `hooks/transcript.mjs` (also imported by the backend's backfill importer, so both read a transcript the same way), `hooks/limits.mjs`, `skills/memory/SKILL.md`. The recall tool is declared by the manifest's `mcp` and served at `/-/mcp`, so cc attributes the caller from its own per-session URL.

## Lifecycle

- **Health vs Hindsight.** cc counts the backend ready on any HTTP answer from `healthPath` within its readiness deadline, and does not kill a child that misses it. So the backend listens and answers `/-/api/health` at once; Hindsight's state is separate and shown in the UI.
- **Start (`ensureRunning`)**, serialized with stop/restart:
  1. wait for a pending detached stop (`stopping.json`, pid alive and recent);
  2. resolve docker (`DOCKER_*`);
  3. validate the saved settings (`SETTINGS_INVALID`, `SLIM_*`, `GPU_NEEDS_*`);
  4. check the API image — Compute `cpu`: the pinned API tag is present (`IMAGE_MISSING`); Compute `gpu`: `API_GPU_IMAGE` is present with its build labels (`GPU_IMAGE_MISSING`, `GPU_IMAGE_MISMATCH`), and the official one is not needed — and that the CP image is present with its base-path/upstream labels (`CP_IMAGE_MISSING`, `CP_IMAGE_MISMATCH`) — never pull;
  5. network and volume: create with labels, or verify the owner (`NAME_TAKEN`) and the volume's embeddings fingerprint (`EMBEDDINGS_CHANGED`);
  6. compose the LLM env (cc-backend reads cc now); with a relay target (Ollama, or a loopback cc backend), run or adopt the relay container (the API image ID the tag resolved to, aliased for that target) and start the tunnel at `<bind>:<relayPort>` with the target, else stop the tunnel and remove an owned leftover relay;
  7. API then CP container, run by the image ID the tag resolved to: missing → `run`; another owner → `NAME_TAKEN`; spec hash or image ID differs → stop, rm, `run` (volume kept); exited → `start`; running and matching → adopt;
  8. wait for API `/health` 200 (detecting an exited container → `CRASHED`, timeout → `UNHEALTHY` with a log tail); Compute `gpu`: the device check (below); then CP `<base path>/api/health`, then sign in to the CP → `ready`.
- **GPU device check.** Upstream picks CUDA when torch sees it and otherwise falls back to the CPU silently, so the only proof is the models' start lines. After the API answers, `docker.logLines` streams the API's log for `[State.StartedAt, StartedAt + apiHealthMs]` (`docker logs --since/--until`, uncapped) into `gpuCheck.deviceReader`; upstream loads both models before it serves, so the lines precede health. Every local model must be on `cuda`, else `GPU_NOT_USED` and the API is stopped (kept). An *adopted* API with lines missing and none naming another device is stopped, removed and run once more, then checked again: a daemon `log-opts` size limit can rotate a long-running container's start lines away (the plugin sets no log options; Docker's `json-file` default keeps everything). A logging driver `docker logs` cannot read fails the check the same way. `docker run` refusals to attach a GPU are classified `GPU_UNAVAILABLE` (`classifyDockerError`).
- **Boot = apply.** Every backend start reconciles to the saved settings, so containers never run a spec the Settings page does not show. `pendingRestart` flags saved-but-not-applied settings while ready.
- **Watch.** While ready, one loop polls API `/health` (each start bumps a token that ends any earlier loop at its next wake, so restarts never stack loops); an exited API, CP or (while linked) relay container is `CRASHED`, a running API failing several consecutive probes is `UNHEALTHY` (`DEFAULT_TIMEOUTS` in `src/supervisor.js`). Docker's `on-failure` restart policy handles transient crashes first. With Compute `gpu`, a healthy tick inspects the API's `State.StartedAt`: a start other than the checked one (an `on-failure` restart) gets the device check again (no recreate), and a failure stops the API with `GPU_NOT_USED`.
- **Stop paths.**
  - *Stop button:* `docker stop` of the containers (and the tunnel), containers and volume kept.
  - *SIGTERM* (cc Stop, Disable, Restart, Update): cc SIGKILLs the process group after a short grace period, too short for Postgres. `shutdown()` spawns `docker stop -t 30 cp api` (plus the relay while linked) **detached** (own process group, outlives the backend), writes `stopping.json {pid, at}`, and the process exits. The next backend waits for that pid before reconciling. The stop uses the current docker invocation, else the last one that worked while still allowed (a settings save or a `DOCKER_DENIED` resets the current one; a remembered `sudo` invocation is never reused once sudo is switched off), else plain docker within a resolve bounded well inside the grace period. When the stop cannot start — no invocation resolves (`DOCKER_DENIED` after a sudo opt-out, an unreachable daemon) or the process fails to spawn — `shutdown-failed.json` records why (no pid-less `stopping.json`), and Status shows it until Hindsight is next ready.
  - *cc restart:* cc re-adopts its running backends without signalling them; nothing happens.
  - *SIGKILL of the backend alone:* containers keep running until the next backend start adopts them.
- **No implicit network or destructive operation.** The start path only inspects, creates the network/volume, and runs/starts/stops/removes this plugin's own containers. Pull, build, load, save, rmi and volume rm happen only in jobs, and only precondition jobs (pull, build-cp, build-gpu, import) may start Hindsight afterwards. (The GPU check's one recreate of an adopted API is a stop/rm/run of the plugin's own container, like a spec change.)

## Image pins

- Images are pinned by tag, never by digest, and upstream's source by its git release tag (`UPSTREAM_TAG`), never a commit hash; no image ID is recorded or compared as trust. The GPU recipe's torch is a version pin (`torch==<version>+<flavour>`), with no wheel hashes. Containers run by the ID the tag resolved to at start, so a re-pulled tag recreates them.
- The build helper is the only image given the Docker socket (root on the host): `runHelper` accepts only the `BUILD_HELPER` tag.

## CP embedding

- The CP image is built from the upstream source with `NEXT_PUBLIC_BASE_PATH=/plugins/code-hindsight`, so its pages, assets, API calls, middleware redirects and router navigation all carry the mount path. The backend proxies every non-shell path to it, putting the base path back that cc stripped.
- The shell page frames the CP same-origin (`iframe[data-cp-frame]`, `src` relative to the mount). On each frame load it copies cc's `dark` class onto the CP document, replaces the CP's `history.pushState` with `replaceState`, and reports the CP path into the shell's query (`?view=cp&cp=…`), which the bridge mirrors into cc's URL.
- A CP link to its own root lands the shell inside the frame; the shell detects `frameElement[data-cp-frame]` and sends the frame to `dashboard`.

## Memory

```
Claude session ── hook.mjs ──► $CONDUCTOR_URL/plugins/code-hindsight/-/hook/* ──► hookRoutes ──► memory.js
                                                                                      ├─ ccSession    describe_session (every call); list_projects (only when a scope needs the workspace)
cc MCP forward ──► /-/mcp (caller.sessionId from cc's per-session URL) ──────────────►├─ scopes       match → banks
                                                                                      ├─ hindsightClient ──► Hindsight API
                                                                                      ├─ retainCursor  memory/cursors.json
                                                                                      └─ activity      logs/memory.jsonl
```

- **The hook stays thin; the backend decides.** The hook sends `CC_SESSION_ID` plus its event data. The backend resolves the session on every call (one `describe_session` carries project, worktree and stage, so nothing is cached and the stage is always current), derives kind from `live.project`, and matches scopes. Retired or unresolved sessions are memoryless.
- **Workspace membership is the one cached fact.** `describe_session` carries no workspace, so `withWorkspace` (`src/scopes.js`, used by `memory.js` and `backfill.js`) asks `ccSession.workspaceOf` only when `needsWorkspace` (`src/scopes.js`) says some scope's outcome depends on it; the answer (or the failure) is put on the session before `matchScopes`. Concurrent callers share one in-flight `list_projects` read, each waiting against its own signal; the read is aborted only when every waiter has given up, so a retain's short deadline neither cuts short a recall's read nor makes the retain wait past its own. `scopeMatches` answers `match` / `no` / `unresolved`; an `unresolved` scope is skipped as `WORKSPACE_UNRESOLVED`, and when it is the first retain scope not ruled out `matchScopes` sets `retainUnresolved`, which `retainForHook` treats like an unresolved session (nothing recorded).
- **Budgets nest.** Recall runs under one deadline, `MEMORY_LIMITS.recallDeadlineMs`, on both the hook and the tool path. It starts when the recall begins, and one `AbortSignal` covers the session lookup, the workspace lookup and the bank fan-out. Banks that answered by then are used; the rest are logged `RECALL_FAILED` per bank; a lookup cut off keeps `SESSION_UNRESOLVED` / `WORKSPACE_UNRESOLVED`. Order: the deadline is below `HOOK_TIMEOUTS.recall`, which is below the recall `timeout` in `hooks.json`; the deadline is below the manifest's `mcp.timeoutMs`, which stays within cc's `MCP_TIMEOUT_CAP`, so the recall tool answers with its own code before cc aborts it. Retain keeps fixed caps: `DESCRIBE_TIMEOUT_MS` + `WORKSPACES_TIMEOUT_MS` is below `HOOK_TIMEOUTS.retain`. The recall hook holds the prompt until it answers. `tests/manifest.test.mjs` pins the order. A timeout, crash or bad JSON never blocks Claude Code, so the worst case of any failure is a memoryless turn.
- **Retain is a persisted cursor with windows, then an append.** The hook sends a bounded tail of parsed turns, never a path. Each Stop records the turns it adds as one **window** in the session's cursor entry (`memory/cursors.json`, keyed by the public session id so it survives `/clear`, renew and transcript rotation), tagged with the bank that stage's first retain scope chose, or none.
  - **Recording (`record`).** A Stop whose tail is *provably* older than the newest recorded end is ignored (`endsAfter`): Stop hooks are separate processes and can arrive out of order. Provable means the previous end is in the tail and the tail ends at an id at or before it (a repeated id counts), or the tail's newest timestamp (or its end turn's) is earlier than the previous end's. Equal timestamps are accepted; sibling turns of one transcript line share one. With no timestamps and no id overlap nothing can be proven, so ordering is **best effort**, and the drain backs it up. A new window replaces the newest one only when both aim at the same bank (or both at none) *and* the incoming tail still contains the newest window's end; otherwise it stays a separate window, so a loss is reported by the drain instead of being swallowed.
  - **Draining.** One worker per session walks the entry in order, drains once more if a Stop arrived while it ran, and stops at the first failure or when Hindsight is not ready. First the unacknowledged batch (`inflight`, resent unchanged under its `operation_id`); then each window — no bank: the cursor just advances past it; a bank: that window's turns (`windowTurns`: after the previous boundary up to its own end, located by turn id, else by timestamp) are appended to `cc-session:<id>` in that bank. With no cursor the first window is the last exchange only (`lastExchangeBoundary`); live retain never backfills (the [backfill importer](#backfill) does, on request). Windows are placed in the newest tail the worker has seen; a late, provably older tail does not replace it. **The cursor never moves backwards:** a window provably at or behind it (same end; earlier in the tail; else earlier by timestamp) is dropped from the list with the cursor left alone and, if it carried a bank, reported as `RETAIN_STALE` (nothing was lost or sent twice).
  - **Attribution.** Windows are persisted before anything is sent, so a Hindsight that is not ready, a failed retain or a restarted backend cannot re-attribute turns: each stretch goes to the bank its own stage chose, and turns from a stage with no retain scope are never sent.
  - **Timestamp fallback.** When a boundary id is gone (rotation, trim), turns are placed by time: after `from`'s timestamp, up to `to`'s. A turn stamped at exactly `from`'s millisecond counts as the boundary turn itself and is excluded (siblings of one transcript line share a timestamp; re-sending the boundary after every rotation would be worse).
  - **Losses are explicit.** `windowTurns` returns `null`, never an empty list, when a window cannot be placed (recorded windows are never empty); the drain logs `RETAIN_DROPPED` and advances. The windows are also bounded by `MEMORY_LIMITS.retainQueueMax`: on overflow the oldest window with a bank becomes one with none and adjacent bank-less windows merge. Nothing is ever sent to another bank.
  - **Corrupt state.** A cursor entry of the wrong shape (`isValidCursor`) is dropped and logged `CURSOR_INVALID`; the next retain starts from the last exchange, without backfilling. A `cursors.json` that is not valid JSON or not an object is moved aside to `memory/cursors.json.corrupt` (replacing an older one), the store starts fresh, and `CURSOR_INVALID` is logged once.
  - **Known unlogged edges.** Two losses are not reported: a window only *partly* placeable in the tail loses its trimmed prefix without a log entry (only a window with nothing placeable is reported); and a turn stamped in exactly the boundary's millisecond is excluded by the timestamp fallback, so a never-sent sibling sharing that millisecond with a boundary whose id is gone is lost silently.
  - Hindsight serializes appends per document and returns the original operation for a repeated id, so a lost response cannot duplicate.
- **Identity is advisory.** See [README → Trust model](../README.md#trust-model).
- **Failures** are logged by `memory.js` as activity entries with a catalog code; nothing at the hook boundary throws.

### Backfill

```
Memory tab ── POST /-/api/jobs/backfill-scan ──► jobs.js ──► backfill.js scan
                                                            ├─ <claudeProjectsDir>/<dir>/<backingId>.jsonl   (listed; streamed once with transcriptTurns)
                                                            ├─ backfillPlacements  hit while size+mtime hold; else ccSession.placeTranscript
                                                            ├─ scopes              withWorkspace → matchScopes(...).retain
                                                            ├─ cursors.peeker()    LIVE_RETAIN_PENDING
                                                            ├─ hindsightClient     live cc-session:<handle> docs (cutoff), cc-backfill:… docs (imported)
                                                            └─ estimate            → latest scan (in memory) → GET /-/api/memory/backfill
           ── POST /-/api/jobs/backfill-import {confirm: true} ──► backfill.js import, per session in scan order:
                                                            lstat (size, mtime, dev, ino) → overlap again → summarise → per part: stored? → operation status → retry | skip | retain → delete orphans
```

- **cc's record is the only placement.** A transcript file name is a backing segment id, not the cc handle (one handle owns several segments; a rotated segment's id shares no prefix with it). `describe_session(<backing id>)` answers `SESSION_NOT_A_HANDLE` with the owning handle; `describe_session(<handle>)` gives project, worktree and last stage, also for sessions of deleted worktrees (cc keeps each session's recorded place). There is no fallback chain: no in-file `cwd`, no directory-name decoding (Claude Code's encoding replaces every non-alphanumeric character with `-`, so it is not reversible), so a transcript is unplaceable rather than misplaced.
- **No cheaper exact interface.** Measured sequentially against one cc host, on retired sessions: `describe_session(<backing id>)` answers in milliseconds, but `describe_session(<handle>)` takes about half a second at the median and about a second at p90, and an unlocatable answer one to three seconds; cc's `GET /api/sessions/<id>/locate` agreed on every sampled session but was no faster (it runs the same per-project location walk), and no route lists a handle's segments. Hence the placement cache, one describe per handle per scan, and sequential calls that leave live hooks their deadlines.
- **Live retain is never disturbed.** Backfill documents are `cc-backfill:…`, never `cc-session:`; backfill reads `memory/cursors.json` only through `cursors.peeker()` (parsed at most once per job run; no cache into the live store, rename or write) and skips running sessions, so it never writes for a handle the live hook is writing for.
- **Idempotent by content.** Parts and their ids are deterministic for an unchanged file under an unchanged cutoff (the import re-checks size, mtime, `dev` and `ino`). "Already imported" means the stored `original_text` hashes to the part that would be sent now, not that the id exists: a cutoff that moved earlier leaves stored parts holding turns live memory now has, and they are replaced (a fresh `operation_id`, which includes the content hash) or, past the new part count, deleted. The scan keeps the plan the user confirms (cutoff, part hashes, orphan part numbers); the import recomputes it and skips a session whose plan differs, so it never sends or deletes anything the dry run did not show. It deletes only the listed orphans, highest first, and the scan's orphan probe crosses gaps (`BACKFILL_LIMITS.orphanProbeMisses`), so no stored part is stranded. The import asks for the document, then the operation, before sending.
- **Bounded memory.** `transcriptTurns` (`claude/hooks/transcript.mjs`) yields turns one at a time; the scan summarises a file in one streaming pass (part sizes, content hashes, first and last turn ids, the cutoff split) and keeps no turn text, so it reads each file at most once. An import summarises, decides per part, then streams again and holds only the part being sent. `BACKFILL_LIMITS.lineMaxBytes`, `documentMaxChars` and `sessionMaxChars` bound a line, a document and a session.
- **Pacing.** One job at a time (shared runner), one Hindsight request in flight, no parallel pool. Cancel aborts the job's `AbortSignal`, which the reader and every fetch take; the job ends `cancelled`, keeping what was sent and what was learned about placements.
- **Live documents another scope wrote.** The cutoff is read from the banks today's retain scopes render for the session. The cursor store cannot add the banks of retired sessions: it names a bank only for unsent turns (a session that has any is skipped `LIVE_RETAIN_PENDING`), and keeps none once they are sent.
- **Upstream relation.** Hindsight's `coding-agents` integration (at `UPSTREAM_TAG`) has its own Claude history importer. The reader rules (`readClaudeTranscript`, `actionLine`, `MEMORY_TAG_RE`) are shared through `claude/hooks/transcript.mjs` (action turns kept, as live retain keeps them); its whole-file streaming read (`readJsonl`) is adapted to an async stream with a per-line cap; "attribute only from an authoritative record" is kept with cc as the authority; its first-turn document timestamp is kept and its synthetic timestamps are not (a part with no timestamp is dated by the file's mtime); its existence check is a per-document read instead of a tag listing. Not taken: one-repo scope, directory-name attribution, retains without `operation_id`, a parallel pool, its own chunking strategy, and batch extraction (server-wide, it would affect live retains).

## Pins and bumping Hindsight

`src/pins.js` holds the version, the upstream release tag (`UPSTREAM_TAG`, derived from the version: the CP is built from the source at it, and it labels the CP and GPU images; no commit hash is pinned), the per-variant image tags, the CP image tag, the build helper (`docker:<version>-cli` by tag; it carries buildx and must not be newer than the daemon's API), and the base path. It also holds the GPU image tag (`API_GPU_IMAGE`) and the CUDA torch flavour and index (`GPU_TORCH_FLAVOR`, `GPU_TORCH_INDEX`); the GPU recipe itself is `src/gpu/Dockerfile`. To bump: update those, run **Build CP image** and **Pull** (or import a bundle), then Start. For GPU compute also: re-diff `src/gpu/Dockerfile` against upstream's `docker/docker-compose/cuda/Dockerfile` at the new tag and carry upstream's changes over (the only intended difference is the uv download settings on the torch install, named in the file's header), re-check the device start lines `src/gpuCheck.js` parses (`Embeddings: local provider initialized`, `Reranker: local provider initialized` in upstream's `hindsight-api-slim/hindsight_api/engine/embeddings.py` and `hindsight-api-slim/hindsight_api/engine/cross_encoder.py`), confirm `download.pytorch.org/whl/<flavour>/torch/` has a wheel for the new base image's torch version, re-check whether the GPU API still needs `TORCH_DISABLE_NATIVE_JIT=1` (`apiSpec` in `src/containerSpec.js`: start the GPU image without it and look for `Failed to find C compiler`), then **Build GPU image** and run `tests/gpu.real.test.mjs`.

- **Relay tests.** `tests/relay.test.mjs` runs the real `src/relay/relay.mjs` as a local child process on port 0, with the real tunnel and proxy, against `tests/support/fakeOllama.mjs` (records requests; `/api/version`, `/api/tags` with a cloud and a local row, canned streamed chat replies; `down` drops connections) and `tests/support/fakeAnthropic.mjs` (records requests; streamed `/v1/messages` replies; `down` and `notFound` switches). The hardening tests run over every entry of `RELAY_TARGETS`. `tests/relay.real.test.mjs` runs the API's own startup LLM check through the real relay container.
- **Fakes.** `tests/fakes/fake-docker.mjs` implements the docker subcommands the plugin uses over a JSON state file (images found by ref or ID; `save`/`load` speak real tar holding a `fake-images.json`) and logs every call; `FAKE_DOCKER_MODE` injects `denied`, `daemon-down`, `port-clash`, `crash`, `no-gpu` (a `--gpus` run or start fails with the daemon's no-toolkit refusal), `fail-<subcommand>`. A run or start sets a new `State.StartedAt`; `logs --since` prints the container's `Log`, which a `--gpus` run fills with upstream's start lines (state `gpuDevice` sets the device, `gpuStartLines: false` omits them). `tests/fakes/fake-sudo.mjs` honours only `-n` (`FAKE_SUDO_MODE=password` refuses). They are wired in through `CODE_HINDSIGHT_DOCKER_BIN` / `CODE_HINDSIGHT_SUDO_BIN`.
- **Isolation.** `tests/helpers.mjs` `mkRoot` gives each test a temp projects root and data dir; `boot` runs `createApp` over the fakes on port 0 with an injected clock and probe. Tests never use the real data dir.
- **No live cc.** `tests/support/ccFront.mjs` reproduces cc's plugin proxy (prefix strip, `X-Forwarded-*`, prefix re-added to every root-relative `Location`, `X-Frame-Options`) for the proxy and browser tests.
- **Memory fakes.** `tests/support/fakeCc.mjs` (programmable `describe_session` per call — live sessions, `retired` handles, transcript `segment`s answering `SESSION_NOT_A_HANDLE`, `unlocatable` ids — `/api/playbooks`, `list_projects` / `list_workspaces` rows with switchable failures — HTTP status, hang, bad shape — a `list_projects` delay (`delayProjects`) and a call log) and `tests/support/fakeHindsight.mjs` (Bearer-checked recall and retain over in-memory banks: append vs replace, per-bank latency, status switches, 404 for an uncreated bank, repeated `operation_id` ignored, in-flight tracking; document reads and deletes, operation status (`opStatus`) and retry; `down` drops every connection). `tests/support/runHook.mjs` runs the real `hook.mjs` as a process.
- **Synthetic transcripts.** `tests/support/transcripts.mjs` writes made-up transcript files (every line kind a transcript holds, malformed and oversized lines) into a temp Claude config dir; `boot` always points `claudeProjectsDir` at a temp path, so no test reads real transcripts. `tests/backfill.test.mjs` drives both backfill kinds through the real job runner over the fakes.
- **Live check.** With `CODE_HINDSIGHT_LIVE_CC=$CONDUCTOR_URL` and `CODE_HINDSIGHT_LIVE_SESSION=<a live session id>`, `tests/memory.real.test.mjs` also boots a scratch backend on a temp data dir and random ports (so the enabled plugin's containers and data are never touched), points its cc at the live one for the read-only `describe_session` and `/api/playbooks` only, writes a scope matching that session's real project, kind and stage, and drives the real hook for recall, retain and recall; a scope for another stage must leave the session memoryless. With `RUN_REAL_CLI=1` it also runs a real `claude -p --plugin-dir claude` against that backend.
- **Real stacks** (`tests/support/realStack.mjs`) use a random `code-hindsight-test-<hex>` prefix and random host ports, and remove their containers, network and volume afterwards, even on failure.
- **Guards.** `tests/supervisor.test.mjs` checks over a full lifecycle that every docker call names only prefixed resources and none connects a network; `tests/frontend-source.test.mjs` scans the UI for HTML sinks, root-relative URLs and the head order.
